# 출시 전 전수 점검표

> **왜 만들었나** — 2026-08-03, N일 주기/휴식 팝업의 시작일 달력이 **iOS에서만** 안 뜨는 버그를
> 출시 직전에 발견했다. 원인은 모달 안에서 여는 모달이 형제 위치에 있어 iOS가 조용히 무시한 것.
> Android는 정상이라 Android 중심 검증에서 그대로 통과했다.
> 진짜 문제는 버그 자체가 아니라 **"안 건드린 화면은 아무도 안 본다"** 는 구조였다.
> 이 문서는 그 구멍을 메우기 위한 화면×플로우 전수 목록이다.

## 사용법

- 한 회차에 한 영역씩 소진한다. 급하게 몰아서 하지 않는다.
- 모든 항목을 **iOS와 Android 양쪽**에서 실제로 눌러본다. 한쪽만 보고 통과 처리 금지.
  (이번 버그가 정확히 그래서 새어나갔다)
- 확인은 스크린샷으로 증거를 남긴다. "될 것 같다"는 통과가 아니다.
- 버그를 찾으면 **즉시 고치고**, 고친 뒤 그 항목을 다시 처음부터 확인한다.
- 한 영역이 끝나면 그 영역의 핵심 경로를 자동 스모크 스크립트로 굳힌다(맨 아래 참고).

범례: `[ ]` 미확인 · `[x]` 양쪽 확인 완료 · `[!]` 버그 발견(아래 "발견 기록"에 적기)

## A. 알람 추가·수정 폼

이번 버그가 나온 곳. 반복방식 6종 × 시작일 달력 경로를 특히 촘촘히 본다.

### A-1. 기본 입력
- [ ] 알람 종류 5종(출근/퇴근/식사/운동/기타) 선택 시 라벨·기본시각이 각각 맞게 채워지는가
- [ ] 라벨 직접 입력, 한글 조합 중 잘림 없는가
- [ ] 시간 피커 상/하 스크롤, 자정 넘김(23→00), 5분 단위
- [ ] 소리/진동 3종(소리+진동 / 소리만 / 진동만) 전환
- [ ] 취소 시 입력한 내용이 있으면 확인을 묻는가 (`isDirty`)
- [ ] 상단 고정바 "추가" 버튼이 미입력 상태에서 비활성(흐림)인가

### A-2. 반복 방식 6종 — 각각 시작일 달력까지
`한 번` / `요일` / `매월` / `매년` / `🔁 N일 주기` / `🌙 N일 후 휴식`

- [ ] **6종 각각에서 시작일 달력이 열리는가** ← 2026-08-03 버그 지점, iOS 반드시 확인
- [ ] 달력에서 날짜 선택 시 닫히고 값이 반영되는가 / 지난 날짜는 선택 불가인가
- [ ] 달력 연도 피커(`2026년 ▾`) 진입·복귀
- [ ] "오늘로 설정" 버튼
- [ ] 배경 탭으로 닫기 / **Android 하드웨어 back으로 닫기**
- [ ] `요일` — 개별 요일 토글, 전부 해제했을 때 동작
- [ ] `매월` — 말일 옵션, 31일 없는 달 처리
- [ ] `매년` — 음력 토글, 음력→양력 미리보기, 윤달·2/29
- [ ] `N일 주기` — 주기 스테퍼(±)·프리셋(2/3/4/7/10/30), "다음: …" 미리보기 4개가 맞는가
- [ ] `N일 후 휴식` — 알람일수/휴식일수 각각, 점 미리보기(●○), 요약 문구
- [ ] 팝업을 닫았다 다시 열었을 때 값이 유지되는가 (iOS 재오픈 포함)
- [ ] 모드를 바꿔가며 왕복했을 때 시작일이 엉뚱하게 초기화되지 않는가

### A-3. 교대근무 게이트 → 근무표 빌더
- [ ] 초번/중번/말번/기타 선택 시 근무표 모드로 전환
- [ ] 신규 진입 시 위저드(RotationWizard) 자동 시작 / 기존 그룹 편집 시 건너뛰기
- [ ] 위저드: 시간대 선택 → 출근 시각 → 퇴근 알람 여부 → 퇴근 시각 → 블록 추가 반복
- [ ] 위저드 안 시작일 달력
- [ ] 빌더: 블록 추가(＋)/삭제/시각 수정/이름 변경/비번 추가
- [ ] 마지막 블록 삭제 → 게이트가 "해당없음"으로 복귀(추가 모드) / 알람 세트 삭제 확인(편집 모드)
- [ ] "여기서 반복" 지정

### A-4. 수정·삭제
- [ ] 기존 알람 편집 진입 시 모든 값이 그대로 복원되는가 (6종 반복방식 각각)
- [ ] 교대근무 알람 편집 — 출근/퇴근 중 어느 쪽으로 들어왔는지 안내 문구
- [ ] "🗑 이 알람 삭제" → 삭제 후 목록/달력/위젯에서 사라지는가
- [ ] 삭제한 알람이 **다시 울리지 않는가** (B-4와 함께 확인)

## B. 알람이 실제로 울리는 경로

경쟁 앱의 최대 약점이자 이 앱의 핵심 가치. **가장 중요한 영역.**
3환경(잠금화면 / 백그라운드 / 앱 포그라운드) 각각에서 확인한다.

### B-1. 울림 — 3환경 × 동작
- [ ] 잠금화면에서 울림 → "끄기" / "5분 후" 각각
- [ ] 백그라운드에서 울림 → "끄기" / "5분 후" 각각
- [ ] 앱 포그라운드에서 울림 → "끄기" / "5분 후" 각각
- [ ] 스누즈 후 5분 뒤 재울림, 반복 스누즈
- [ ] 소리/진동 설정이 실제 울릴 때 반영되는가 (3종 각각)
- [ ] 알람 볼륨 설정이 반영되는가

### B-2. 안 울려야 할 때 안 울리는가 (이중 시스템)
- [ ] 알람 스위치 OFF → 그 시각에 **울리지 않는가** (Expo + AlarmManager 둘 다 취소됐는지)
- [ ] 알람 삭제 → 울리지 않는가 (`syncActiveNativeAlarms` 경로)
- [ ] 여러 알람 중 하나만 OFF → 나머지는 정상 울리는가 (게이트 오판 없는지)
- [ ] 전부 OFF → 게이트가 fail-open으로 열려 다 울려버리지 않는가 (`ACTIVE_IDS_NONE`)

### B-3. 복구·내구성 (Android)
- [ ] 재부팅 후 예약 복구 (`BootReceiver` + `AlarmStore`)
- [ ] 앱 업데이트(재설치) 후 복구 (`MY_PACKAGE_REPLACED`)
- [ ] Direct Boot — 재부팅 후 **첫 잠금해제 전**에도 울리는가
- [ ] Doze 모드 / 배터리 최적화 켠 상태에서 정확한 시각에 울리는가
- [ ] 폴더블(`플립`) 닫힘 상태 커버 디스플레이에서 울림·끄기

### B-4. 반복 주기가 실제로 맞는가 (날짜 넘겨서)
- [ ] `요일` — 지정 요일에만
- [ ] `N일 주기` — 시작일 기준 N일 간격, 미리보기에 나온 날짜와 실제가 일치
- [ ] `N일 후 휴식` — 알람일수 뒤 휴식일수만큼 건너뛰는가
- [ ] `매월`/`매년` — 말일·음력·윤달 케이스
- [ ] 교대근무 순환표가 주기대로 도는가

### B-5. 워치 (best-effort)
- [ ] 워치에 알림이 전달되는가
- [ ] 워치에서 닫기(스와이프)했을 때 폰 쪽 후속 로직이 어긋나지 않는가
      (iOS는 `customDismissAction: true` 필요 — 전역 규칙)

## C. 달력 · 위젯 · 설정

### C-1. 달력 탭
- [ ] 근무일/비번 색 표시
- [ ] **근무 시간대 라벨(초번/말번)이 셀 맨 위에** 표시되는가 (확정 요구사항)
- [ ] 시간대 없는 알람이 대표로 뽑히지 않는가 (2026-07-13 수정 건 회귀 확인)
- [ ] 연도 피커, 월 이동
- [ ] 날짜 탭 → 그날 알람 상세 모달
- [ ] 알람 추가/수정/삭제가 달력에 즉시 반영

### C-2. 위젯
- [ ] 활성 알람이 위젯에 반영
- [ ] 알람 ON/OFF·삭제 시 위젯 갱신
- [ ] 재부팅 후 위젯 상태

### C-3. 설정
- [ ] 글자크기 — 변경 시 **앱 전체 텍스트에 반영되는가** (새 텍스트가 `AppText` 래퍼인지)
- [ ] 테마 다크/라이트 — 모든 화면·모달에서 색이 깨지지 않는가
- [ ] 알람 볼륨 슬라이더
- [ ] 앱 버전 표시

### C-4. 목록 화면 / 기타
- [ ] 알람 카드 스위치 ON/OFF — **오탭 방지**가 유지되는가 (2026-08-02 수정 건)
- [ ] 세로 스와이프 동작
- [ ] 프로모 배너 롤링(무한루프)
- [ ] 개발자 응원하기 → 계좌번호 복사 버튼, **Android 상태바 침범 없는지**
- [ ] 사용법 안내(HelpScreen) 전체 문구·링크

## D. 튜토리얼 · 첫 실행 경험

- [ ] 신규 설치 직후 빈 상태 화면
- [ ] 첫 실행 권유 팝업 → 근무표 만들기 따라하기 진입
- [ ] **근무표 따라하기 15단계 완주** — 각 단계 스포트라이트가 올바른 위치를 가리키는가
      (Android는 `measureInWindow`가 상태바만큼 짧게 나오는 이슈 있음 — 보정 확인)
- [ ] 따라하기 중간에 탭을 옮기거나 취소했을 때 상태가 깨지지 않는가
- [ ] **N일 주기 따라하기 11단계** — 6단계(시작일자)가 이번 버그로 막혀 있었다. 수정 후 완주되는지 확인
      ⚠️ 단, `tutorialSteps.ko.ts` 주석에 따르면 **현재 이 시나리오는 진입점이 없다**
      (배너·첫실행 팝업이 모두 근무표 따라하기로 일원화됨). 살릴지 지울지 결정 필요
- [ ] 권한 요청 흐름(알림/정확한 알람/배터리 최적화 제외) 안내가 뜨는가

## 자동 스모크로 굳히기

각 영역을 손으로 훑어 통과시킨 뒤, 그 영역의 **핵심 경로만** 자동 스모크로 옮긴다.
손 점검은 넓게, 자동화는 좁고 확실하게 — 자동화가 손 점검을 대체하지 않는다.

- `./scripts/test-alarm-suite.sh --static` — 정적 규칙(모달 중첩 등). 커밋 전 항상
- `./scripts/test-alarm-suite.sh <adb-serial>` — Android 기기 검사
- **(신설 예정)** iOS 시뮬레이터 스모크 — 현재 도구에 iOS 검증 경로가 전혀 없다.
  이번 버그가 iOS 전용이었던 게 우연이 아니다. A·B 영역을 훑으며 확정된 경로부터 스크립트화한다.
